# Isolated candidate discovery

Phase 05: proposals and review workflow only. No runtime integration, production writer, membership grant or methodology calculation. Python standard library, supported Python 3.12; uses the phase-04 graph and its checksum validation.

## Run small tests

```sh
/usr/bin/python3 associativvordes/candidate_search/test_search.py -v
node --test tests/associative-candidate-search.test.mjs
```

The 18 source observations are genuine, pinned UDer/MorphyNet records. Fixture attribution and provenance are in `fixtures/`. Test-only mutations are explicitly adversarial and never exported as real corpus examples.

## Replay the bounded pilot

First reproduce the phase-04 graph and original registry cache as described in `../evidence_graph/README.md`. Use external directories, never the repository, for mutable queues and outputs. Substitute paths below with those generated by that replay.

```sh
/usr/bin/python3 associativvordes/candidate_search/prepare_frequency.py \
  --original /tmp/registry-original --lock /tmp/registry/v6-lock.json \
  --snapshot /tmp/graph/BUILD_ID --output /tmp/candidate-frequency
/usr/bin/python3 associativvordes/candidate_search/search.py \
  --snapshot /tmp/graph/BUILD_ID --queue /tmp/candidate-review.sqlite \
  --frequencies /tmp/candidate-frequency/frequencies.json \
  --frequency-lock /tmp/candidate-frequency/frequency-lock.json \
  --output /tmp/candidate-run --families OCUL PEDE ALTER REGUL CREAT NAT INTER
/usr/bin/python3 associativvordes/candidate_search/pilot.py \
  --snapshot /tmp/graph/BUILD_ID \
  --frequencies /tmp/candidate-frequency/frequencies.json --output /tmp/candidate-evaluation
```

`--weights FILE` accepts an object containing exactly the six integer weights in `DEFAULT_WEIGHTS`. Default discovery uses 12 starts/family, balanced across available languages, productive directed arcs first, depth 2, 20 returned paths/start and 300 expansions/start. The library supports up to 50 starts and depth 3; an explicit scope of at most seven distinct families is required. GLeMM unknown-direction pattern pairs remain in the evidence graph; they are not silently promoted to directed derivations.

`Queue.decide(id, state, reason, actor)` records a decision with the current evidence fingerprint. Permitted workflow states: open, rejected, reviewed, split_required, deferred. `reviewed` never means accepted family membership. Rebuild with the same SQLite queue to retain decisions; use `Queue.export` for deterministic NDJSON backups. Keep the SQLite database itself as the authoritative history backup; rebuilding a graph never deletes it. No automatic deletion of inactive questions. Reverse new-base proposals use a separate persistent database `<queue>.reverse`, exported as `reverse-queue.ndjson`; `unassigned` is a workflow label, not a canonical root. Rejections and history persist there as well.

Stable IDs identify a review question at family/language/NFC+casefold lemma/POS, not a merged lexical entity. Source-native alternatives, paths, original source references and homonym uncertainty remain separate. POS changes inherit conservative spelling-scope negative decisions; reviewer resolution is required rather than automatic recovery via a new question. Exact allomorph checks require both a real source lexeme and an actual finite project lemma ID covered by a pinned accepted realization. Fuzzy classification is a separate opt-in hypothesis helper over real lexemes and does not add queue records or authorize a rule.

Source-local evidence changes alter only affected question payloads/fingerprints. Discovery currently reruns the bounded selected scope; this is not a million-record incremental traversal engine. Reconciliation deactivates stale scope references but never removes questions/history. SQLite supports a persistent disk queue; JSON frequency extraction reads one pre-existing member shard at a time. The pilot groups fit in bounded memory; this is intentionally not a full-corpus scan or full production search index.

Reports and observed limitations are in `audit/associative-external-preparation/05-CANDIDATE-SEARCH-REPORT.md` and adjacent phase-05 documents. No accuracy, membership, lexical identity or priority calibration claim follows from successful import/search.
