# Массовая разметка ассоциативных семей

Это локальное приложение для исследовательской разметки. `ACCEPT_PROPOSED` одобряет кандидатуру; оно **не записывает членство**, не создаёт основу и не снимает исторический запрет. У сервера нет маршрута применения изменений к production. Используются общие компоненты оформления `shared/ui.css`, форматы и устойчивые ID существующей очереди `candidate_search`; старые статусы очереди не переопределяются.

## Запуск

Нужны Linux/macOS, Python 3.12+, браузер и постоянный локальный диск с POSIX `flock`, атомарным переименованием и `fsync`. Внешние Python-пакеты не нужны. Каталог данных должен находиться вне checkout; не используйте `/tmp`, эфемерный контейнер или сетевой диск как единственное хранилище.

Из корня репозитория, подставив постоянные абсолютные пути:

```bash
python associativvordes/review/server.py --data /srv/interal-review init \
  --queue /srv/mass02/exports \
  --reviewer annotator-a:reviewer --reviewer annotator-b:blind --reviewer adjudicator:arbiter
python associativvordes/review/server.py --data /srv/interal-review serve --port 8765
```

Откройте `http://127.0.0.1:8765`. Администратор передаёт каждому разметчику только его ключ из приватного файла `/srv/interal-review/credentials.json` (права 0600). Для входа не требуется редактировать JSON. Идентификаторы должны быть псевдонимами, а не email или ФИО. Ключи не входят в резервные копии. На общей машине используйте отдельные профили браузера для разных разметчиков.

Сервер слушает только loopback, проверяет Host/Origin, требует сессионную cookie и CSRF для изменений. Он рассчитан на доверенную локальную машину; внешний доступ, TLS, управление пользователями организации и публичное размещение не входят в этот протокол. Обычные страницы сайта на Vercel не получают журнал и ключи. Общий CSS используется без внешней загрузки шрифта.

## Работа разметчика

1. Выберите язык, семейную область, проблему и свой статус. «Без моего решения» показывает оставшуюся работу. «Группировать близкие» упорядочивает однотипные вопросы; кнопка ≡ оставляет одну группу. «Сомнительные случаи» включает нерешённую идентичность. Фильтр независимости требует двух **явно установленных** групп: три названия ресурсов сами по себе этого не доказывают; в текущем mass02 независимость неизвестна.
2. Откройте слово. В карточке есть лексемы с исходным написанием, нативными ключами и POS, ссылки членства/якорей, пути, отдельные инфлекции, исходные утверждения, версии, локаторы и хеши, история, частотные наблюдения. Направление `unknown`, неустановленный смысл и непроверенный POS сохраняются таковыми. Приоритет — эвристика, не вероятность.
3. Выберите конкретную нативную лексему, тип связи и основание. По умолчанию стоит `UNCERTAIN`. Доступны все шесть статусов протокола. «Сохранить и далее» фиксирует решение и открывает следующий вопрос. Отказ относится только к указанным семье, языку и лексеме; другие семьи не получают отказ автоматически.
4. Для исправления откройте вопрос через фильтр своего статуса и сохраните новое решение. «Отменить последнее решение» требует основания и добавляет компенсирующее событие. Ошибочная запись остаётся в истории. Повторная отмена отменяет последнее событие, а не стирает журнал.
5. Пакет: в каждой карточке явно выберите лексему/тип/основание и нажмите «Добавить в пакет принятия». При необходимости удалите карточку из пакета. Затем откройте предпросмотр. Допускаются только одинаковые семья, язык, POS, набор морфологических категорий и выбранный тип связи. Подтверждение сохраняет отдельное решение для каждого вопроса одной атомарной транзакцией. Без действительного предпросмотра пакет не принимается. Изменившиеся решения/источники делают его устаревшим; после перезапуска предпросмотр нужно собрать снова.
6. Прогресс, последний вопрос и фильтры сохраняются на сервере для каждого псевдонима. Несохранённый текст карточки хранится локально в профиле браузера под этим псевдонимом; это черновик, не решение. При конфликте 409 откройте карточку заново. Повтор того же запроса с тем же ID не создаёт новое событие.

## Исходные строки

Mass02 экспорт содержит точные локаторы и хеши, но не оригинальные байты строк. Для просмотра текста подключите существующие сертифицированные снимки импортёров из промпта 01:

```bash
python associativvordes/review/server.py --data /srv/interal-review attach-rows \
  --snapshot /srv/catalog/uder-v1.0.2 \
  --snapshot /srv/catalog/morphynet-eng-v1.0.2
```

Можно повторять `--snapshot` для всех опубликованных разделов UDer, GLeMM и MorphyNet. Команда потоково читает `records.ndjson.gz`, проверяет хеш из `manifest.json`, затем совпадение evidence ID, локатора, версии и SHA256 исходных байтов. В хранилище сохраняются только строки вопросов текущей очереди; они входят в полную резервную копию. Отчёт показывает attached/wanted/missing. При отсутствии снимков интерфейс сообщает об этом и даёт ссылку на исходный ресурс, номер строки и хеш; он не выдумывает текст. Сетевой запрос по произвольному URL карточки сервер не выполняет.

## Слепая проверка и арбитраж

Для второго разметчика администратор выдаёт отдельный ключ роли `blind`. Сервер передаёт только нейтральную пару «лексема — семейная область», исходные утверждения/строки ресурсов, частотные наблюдения и собственную историю. Он не передаёт решения первого, прежние запреты, членство, ожидаемый ответ, приоритет, категории, алгоритмические пути и основы. Фильтры алгоритмических проблем, групп и разногласий игнорируются в этом режиме. Даже экспорт и исследовательский overlay недоступны этому ключу.

Ключ `arbiter` открывает сравнение только после наличия первичной и слепой проверок. Фильтр «Разногласия» сравнивает статус, лексему и тип связи. Арбитр выбирает лексему и сохраняет собственное решение с основанием; `UNCERTAIN` допустим. Арбитраж привязан к хешу обеих проверок. Если они меняются, повторная запись со старой карточки отклоняется, а прежний арбитраж помечается устаревшим в overlay. Данные первичных проверок не переписываются.

## Новые источники, исследовательский слой

```bash
python associativvordes/review/server.py --data /srv/interal-review import --queue /srv/mass02-next/exports
```

Лучше остановить сервер на время административного импорта; файловая блокировка также защищает параллельный импорт. Все старые снимки и решения остаются. Временно исчезнувший вопрос сохраняет историю и получает её обратно при повторном обнаружении с тем же ID. Карточка отмечает обновление снимка после решения. Новые ID не получают автоматического лексемного тождества по одинаковому написанию; исходная история очереди видна первичному разметчику.

`GET /api/overlay` доступен арбитру и возвращает только исследовательские одобрения с `establishes_membership:false`, ссылкой на старый снимок и флагами устаревания. Это отдельный слой для просмотра после пересчёта графа. Любое утверждённое изменение семей требует отдельного процесса проекта; кнопки применения здесь нет.

## Сохранность, экспорт и восстановление

Авторитет — `events/0000000001.json` и последующие неизменяемые транзакции с хеш-цепочкой, а не SQLite. Запись идёт в отдельный файл, затем `fsync`, атомарное переименование и `fsync` каталога. Пакет публикуется целиком. HEAD обнаруживает потерю уже подтверждённого конца журнала. Незавершённые `.pending-*` не воспроизводятся; повреждение/разрыв подтверждённой цепочки останавливает открытие. Блокировки сериализуют процессы; ревизии защищают от потери обновления внутри одного потока разметчика. Разные разметчики имеют отдельные потоки решений.

Арбитр нажимает «Скачать резервную копию»: ZIP содержит версионированный экспорт всей цепочки, **все использованные снимки вопросов**, подключённые исходные строки и прогресс. Сохраняйте копии на независимом постоянном носителе. Они содержат псевдонимы и основания, поэтому не публикуйте их как публичную разметку без проверки. Никаких email/ФИО приложение не требует.

```bash
python associativvordes/review/server.py --data /srv/interal-restored restore --backup /backup/review-backup.zip
python associativvordes/review/server.py --data /srv/interal-restored accounts \
  --reviewer annotator-a:reviewer --reviewer annotator-b:blind --reviewer adjudicator:arbiter
python associativvordes/review/server.py --data /srv/interal-restored serve
```

Восстановление разрешено в пустой каталог и проверяет цепочку, имя-хеш экспорта и хеши всех исторических снимков. Используйте прежние псевдонимы и роли, чтобы продолжить их потоки. Ключи создаются заново. CLI `export` создаёт также проверяемый JSON журнала, но отдельно от снимков это **не полная** резервная копия.

## Испытания и измерения

```bash
python -m unittest discover -s associativvordes/review -v
npm ci
npx playwright install chromium
```

Для браузерного сценария создайте отдельное тестовое хранилище реального mass02 экспорта с тремя ролями, запустите сервер и выполните:

```bash
REVIEW_BASE_URL=http://127.0.0.1:8765 \
REVIEW_CREDENTIALS=/srv/interal-review-test/credentials.json \
REVIEW_REPORT=/srv/reports/browser.json \
REVIEW_BACKUP=/srv/reports/review-backup.zip \
node tests/browser/associative-review.playwright.mjs
```

`CHROMIUM_EXECUTABLE_PATH` позволяет использовать уже установленный Chromium. Скрипт рассчитан на исходную реальную очередь из 1 567 вопросов, создаёт **тестовые** решения и не должен запускаться на рабочем журнале людей. Для воспроизводимой проверки движка:

```bash
python associativvordes/review/exercise.py --queue /srv/mass02/exports \
  --data /srv/review-qualification --report /srv/reports/review03
```

Отчёты целостности, истории и производительности за 2026-10-21 находятся в `audit/associative-external-preparation/review03/qualification-20261021/`. Браузерная автоматизация не заменяет исследование удобства работы с людьми. Текущие пределы измерены на 1 567 реальных вопросах, не на миллионах; интерфейс выдаёт страницы по 50–100 записей, сервер держит текущий экспорт в памяти.
