# Промпт 04 — измерение качества до массовой разметки

Новый эксперимент находится рядом с прежним пакетом: `protocol04.json`, `runtime04.mjs`, `compare04.py`, `metrics04.py`, `study04.py`, `human04.py`, `replay04.py`. Прежние predictions сохранены как исторические и не используются как текущая оценка. Семьи не изменяются.

## Что зафиксировано

База кода A: `f8b399c835dca054fe8f43d735a97a85df734e29`. Фиксированы исходные 1 406 случаев и 381 обязательная повторная проверка; case-set SHA256 `3f809f5f36ea367e03c1b0bf29d4f95244f81db2df15a33c94b39e7c8c2d38a1`. Файлы CASES/ANNOTATION-TASKS и исходный SAMPLING-MANIFEST из `audit/associative-external-preparation/pilot-validation/` не переписываются. Новый граф и код имеют отдельные контрольные суммы.

Версии: UDer 1.1; MorphyNet `378144f64df58c78db5245af19d16a511ccecf3a`; GLeMM 2.0 `395020177a96a81177582fb59664509ff015f934`. Flexor исключён. Источник и исходная строка не являются gold.

Общий лимит выдачи — 20 групп написаний на семью и язык. Для внешней морфологии: один фиксированный сбалансированный список до 8 native starts на ячейку, глубина 2, до 20 путей и 300 раскрытий на старт. Набор starts выбирается до абляций. Неактивные источники не создают мостов и не расходуют бюджет раскрытия. Неизвестное направление допускается только как терминальная гипотеза. Инфлекции не становятся деривационными путями. Сложные, смешанные и неопределённые пути учитываются отдельно.

A исполняет настоящие `createCandidateIndexLoader.loadCandidateEntries` и `findCandidatesForRoot`, как на странице инструмента, с `groupModels:false`. Файловый транспорт заменяет HTTP, но не логику поиска: проверяются Git blob и SHA256 реально прочитанных ресурсов. Сам факт наличия слова в реестре не записывается как prediction. Модели для семантической оценки не вызываются. A — сравнение этапа **генерации кандидатов**, не полной последующей оценки международности.

B объединяет фактическую выдачу A с UDer, чередует потоки и применяет тот же конечный лимит. U, C и D используют соответственно UDer; UDer+MorphyNet; UDer+MorphyNet+GLeMM. При добавлении источников исходные кандидаты могут вытесняться; оба списка сохраняются. Группировка написаний служит только выдаче и бюджету, не устанавливает тождество нативных лексем/значений. Для внешнего пути требуется совпадение native ID случая; для A фиксируется собственная ограниченность поиска по написанию.

Неизвестные частота/значение/POS не заменяются нулём или установленным фактом. Частота A сохраняется в исходных полях runtime; для внешних кандидатов без наблюдения — null. Отсутствие поддержки даёт abstain, а не ручной отрицательный ответ.

## Повтор эксперимента

Нужны Node 22 и Python. Для совпадения опубликованной сборки графа используйте Python 3.12.3, SQLite 3.45.1, Unicode 15.0.0; версии и хеши записаны в GRAPH-MANIFEST/EXPERIMENT. Используйте исходные кэши промптов 01–02. `registry-cache` содержит проверенные Git-файлы v6 согласно `prepare_registry.FILES`; `raw-root` — 35 закреплённых морфологических файлов.

```bash
python associativvordes/pilot_evaluation/replay04.py \
  --registry-cache /srv/registry-original --raw-root /srv/morphology-raw \
  --output /srv/pilot04-replay
```

Выход должен быть новым каталогом вне checkout. Скрипт заново отбирает реальные строки, строит граф, копирует **существующие** frozen cases, готовит независимые задания, запускает A и все пять конфигураций. Он не создаёт ответы людей.

Для повторного сравнения на готовом графе:


## Независимые люди и время

Статус поставляемого пакета — **BLOCKED: нет зарегистрированных проверенных человеческих разметчиков**. Автоматизированные тесты используют только явно TEST_ONLY данные и никогда не становятся gold.

Заранее выбран первый этап: 180 случаев во всех 72 ячейках семья×язык. В 37 ячейках — 3 случая, в 34 — 2, в одной редкой ячейке всего один доступный случай. Дефицит не заполняется вымышленными словами. Это предварительная подвыборка, не итоговая оценка всех семей.

Для каждого случая предусмотрены две независимые эталонные проверки **без подсказок тестируемого алгоритма**, затем по одной проверке другими людьми в условиях control и combined. Нужно 360 эталонных проверок + 360 измерений времени, а также арбитраж разногласий. Два gold-слота, четыре слота измерения времени; участники должны быть разными людьми и владеть назначенными языками. Для разногласий нужен отдельный арбитр. Псевдонимы, языковая компетенция и независимость подтверждаются владельцем проекта; программа не может удостоверить личность или распознать ложное заявление «я человек».

Первичная эталонная группа и группа измерения времени не пересекаются. Один участник никогда не получает один случай повторно и не получает одну leakage group в разных условиях. Назначения групп зафиксированы хешем до человеческих ответов; каждый участник группы времени получает обе условия на разных группах. Gold не извлекается из эффективности, исходных корпусов, accepted-статусов, путей или LLM.

Готовый `study/` имеет пустой приватный реестр. После реального подтверждения людей администратор регистрирует их командами такого вида:

```bash
python associativvordes/pilot_evaluation/human04.py --data /srv/pilot04/study register \
  --annotator PERSON_PSEUDONYM --slot gold-1 --languages en,de \
  --authorized-by PROJECT_OWNER --authorization-ref PRIVATE_VERIFICATION_REFERENCE
python associativvordes/pilot_evaluation/human04.py --data /srv/pilot04/study readiness
python associativvordes/pilot_evaluation/human04.py --data /srv/pilot04/study serve --port 8767
```

Остальные слоты: gold-2, study-1, study-2, study-3, study-4; при необходимости arbiter. Не регистрируйте имитации и модели как людей. Без проверенного реестра сервер отказывается начинать сбор. Личный ключ выводится один раз; сообщается только соответствующему человеку. Интерфейс доступен на `http://127.0.0.1:8767`, использует общий стиль Interal и не требует редактирования JSON. Он показывает только назначенную карточку, не ответы других людей и не predictions. Combined показывает исходные наблюдения со статусом неопределённого тождества, без алгоритмических путей/рангов/предложенного ответа.

Для yes/no нужны конкретное значение, POS и независимое словарное/грамматическое свидетельство с точным локатором и выводом. При нехватке оснований остаётся uncertain. В поле значения желательно использовать устойчивый идентификатор словарного значения; разные формулировки могут потребовать арбитража.

Таймер работает на сервере; пауза и скрытие вкладки приостанавливают отсчёт. После прерывания полное время сохраняется как unknown, не ноль. События атомарны, имеют хеш-цепочку и подтверждённый HEAD, повтор запроса не создаёт дубль. Для разногласий остановите сервер и создайте независимые задания:

```bash
python associativvordes/pilot_evaluation/human04.py --data /srv/pilot04/study adjudication-tasks
python associativvordes/pilot_evaluation/human04.py --data /srv/pilot04/study export
```

Арбитр не видит прежние ответы. Экспорт создаёт неизменяемый каталог по хешу с judgments.ndjson, adjudications.ndjson, trials.ndjson и реестром без ключей. Сохраните весь приватный каталог study и независимую резервную копию на постоянном диске. При пересчёте передайте эти файлы через `--judgments`, `--adjudications`, `--trials`, `--raters`, а также тот же `--study`. Первые 180 случаев не получают gold после одной проверки, даже если frozen case первоначально требовал только одну.

Полный исходный пилот требует как минимум **1 787** ручных проверок: 1 406 первичных + 381 повторная, без арбитража. Две проверки всех 180 случаев могут дополнительно увеличить это число для случаев, не включённых в исходные 381; конкретное пересечение указано в STUDY.json.

## Метрики и допуск

TP/FP/FN/TN и знаменатели считаются только по независимому определённому gold, отдельно для evaluation split, языка, семьи и типа отношения. У uncertain, спорных и неполностью перепроверенных случаев нет выдуманных ответов. Отдельно считаются abstain всей выдачи, ошибки членства, типа связи, явного объединения семей, дополнительные/вытесненные правильные случаи, согласие, Cohen kappa. Если объединение семей не предлагалось явно или нет разметки риска, его частота — null, не доказанные «0 ошибок».

Для долей выдаются интервалы Wilson 95%; для согласия — Wilson и bootstrap kappa. Это интервалы ограниченной области; зависимость слов одной основы и обогащённая опасными случаями выборка не позволяют считать их популяционной гарантией. Ускорение использует только измеренное человеческое время и независимый gold, с bootstrap по участникам и leakage groups. Время ложных/неопределённых кандидатов не удаляется из затрат. При недостающем времени или gold ускорение BLOCKED. Неизвестные и ненаблюдённые величины не становятся нулём.

Пороги — **предварительно установленные цели допуска, не измеренная точность**: нижняя односторонняя граница precision 99%, верхняя граница риска ложного объединения 0.1%, семейная alpha 0.05 / 12 заранее определённых страт (6 языков × 2 возможных класса). При нуле ошибок это требует не менее 546 независимых единиц на страту для первой цели и 5 478 для второй. Эти минимумы условны: независимость и репрезентативность должны быть подтверждены, ненулевые ошибки увеличат объём. Имеющиеся 1 406 случаев не дают такой гарантии по каждой страте.

**Сейчас допустимо автоматизировать** проверку целостности, импорт, точную дедупликацию native IDs, генерацию предложений, распределение заданий и расчёт метрик после получения gold. **Автоматические положительные membership и объединения семей не допускаются.** Все смысловые решения требуют человека; омонимия, compound/mixed path, неясные направление/POS/значение, отрицательная история и конкурирующие семьи требуют второй независимой проверки. Полезность источников по языкам пока описывается только фактической выдачей, а не числом правильных находок.
