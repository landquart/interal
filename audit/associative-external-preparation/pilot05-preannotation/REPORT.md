## Допуск к автоматизации

Разрешены автоматические проверки целостности, подготовка и группировка карточек, отсечение недопустимого пути как пути, кеширование, предварительные предложения и маршрутизация человеку. **Семантическое положительное/отрицательное решение, окончательное включение и объединение семей не допущены к автоматизации.** Все proposals требуют review, reliability=null. Численных порогов по этим данным не подбирали.

Чтобы получить первое сравнительное измерение, нужны реальные сохранённые ответы B/C на тех же случаях и бюджете, а также **360 независимых человеческих gold-проверок заранее закреплённых 180 случаев**; арбитраж разногласий — дополнительно. Для полного исходного пилота минимум **1 787 gold-проверок** (1 406 + 381). Для оценки ускорения отдельно нужны **360 измеренных проверок времени** в control/LLM условиях, разными людьми без повторного предъявления leakage group между условиями. Эффект ложных кандидатов входит во всё затраченное время. Старые morphology-only trials не подменяют этот эксперимент.

После этого нужны отдельная калибровочная выборка и нетронутый сгруппированный holdout; статистические пороги остаются согласно заранее закреплённому протоколу 04. До получения этих данных невозможно добросовестно назвать точность, экономию труда или надёжные языки/типы для автоматических положительных решений.

Команды всех режимов, подключения источников, бюджета, resume и восстановления: [README](../../../associativvordes/auto_annotation/README.md). Frozen offline benchmark выполняется отдельным CI job без внешних credentials. Реальный массовый запуск требует сертифицированных индексов промпта 02 с hashes из input lock; без них не следует подменять проверку состояния реестром или тестовыми строками.

Восстановление точных опубликованных JSON:

```bash
python3 associativvordes/pilot_evaluation/archive04.py \
  audit/associative-external-preparation/pilot05-preannotation/PACKED-RESULTS.json.gz \
  /srv/interal-research/pilot05-unpacked
```

Получаются `PROPOSALS.json` и `HUMAN-STUDY.json`. Полный рабочий store восстанавливается отдельным backup/restore из README; этот архив отчёта его не заменяет. Атрибуция и лицензии исходных ресурсов остаются согласно закреплённым source-lock/ATTRIBUTION этапов 01–04; новые словарные свидетельства не выдуманы.
