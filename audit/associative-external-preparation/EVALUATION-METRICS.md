# Метрики и допустимая интерпретация

Основная оценка — `primary_evaluation` на зафиксированном evaluation split. `overall` и development — описательные срезы. По каждому language, family, основному вручную установленному relation и split выдаются те же числители/знаменатели. Метки типов из ресурсов не подставляются вместо ручных relation.

| Показатель | Определение |
|---|---|
| Precision | TP/(TP+FP) для положительных предложений с определённым gold |
| Recall размеченной области | TP/(TP+FN); gold-positive abstain входит в FN |
| Ошибки членства | Явные yes/no, не совпавшие с gold; частота = ошибки/(размеченные − abstain) |
| Ложные объединения | Предсказанная группа минимум из двух family ID содержит недопустимую по gold семью; единичное ложное членство учитывается отдельно |
| Ошибки границ | Неравные списки codepoint offsets на одном target; только когда обе стороны предоставили сравнимые границы |
| Уникальные находки | Уникальные правильные case ID; число независимых моделей выдаётся отдельно только при ручных independent_model_id |
| Вклад ресурса | Добавленные/потерянные правильные case и изменение FP в парном сравнении на том же gold |
| Спорная доля | disagreement + итоговый uncertain / случаи хотя бы с одним ручным ответом; незавершённый обязательный второй ответ отдельно |
| Ручная проверка | Доля requires_manual_review по всем предсказаниям; отдельно — по определённому gold |
| Скорость | Наблюдённое время конфигурации и полный replay; не переносится на миллионы записей |
| Качество разметки | Попарное согласие decision/relation и Cohen κ decision по двум независимым авторам; нет пар/нет дисперсии → null |

Нулевой знаменатель → null, никогда не «0% точности» или «100% успеха». Неразмеченные, незавершённые, спорные и uncertain cases не объявляются отрицательными. Отсутствующая сегментация или непроверенные семейные группы означают отсутствие оценки, а не отсутствие ошибок. В текущем source runner boundaries=null; без сопоставимых явных исходных/actual-runtime offsets численная оценка границ недоступна. Автоматически угадывать их по stem нельзя.

Все source-предложения требуют проверки. Источники не принимают членство; yes в RUNS означает положительное предложение для проверки. A должен быть реальной выгрузкой действующего поиска на замороженном коде и той же области. `capture.py` сохраняет найденные runtime-слова и исходные частотные/model поля. Только явно полный, неусечённый поиск позволяет no при отсутствии слова. Нет выгрузки/есть усечение — abstain. Без A нельзя заявлять выигрыш B над A.

A→B выделяет добавление UDer к A. U→C — добавление MorphyNet к UDer-only. C→D — добавление GLeMM. B→C — изменение сразу двух факторов, его нельзя называть чистым вкладом MorphyNet. D→E разрешён только после отдельной проверки Flexor. При ограниченных бюджетах добавление ресурса может как добавить, так и вытеснить случаи, поэтому публикуются оба множества. Количество новых предложений без gold не равно количеству новых правильных находок.

GLeMM/MorphyNet имеют зависимое происхождение; несколько строк не являются независимыми подтверждениями. Родственные варианты и близкие производные не должны искусственно увеличивать число независимых моделей; для этого нужны отдельные ручные группы и диагностические captures. Большая общая точность базы не переносится на точность ассоциативных семейств.

Выборка из проектных записей и доступных внешних путей не является случайной выборкой всех слов языка. Условный recall на 1406 случаях не является глобальным recall. Межэкспертное согласие на обогащённом prior-decision подмножестве не является общей надёжностью всех аннотаций. Нужны явные размеры и пропуски каждого среза.

## Диагностика расчётов

`impact.py` сравнивает два сохранённых actual-runtime результата: тот же case-set, версия методологии и неизменные SHA-256 кода, шесть явных состояний языков. Сравниваются записанные упорядоченные top five (включая смену порядка), новые вручную обоснованные independent_model_id, представленные языки, потеря frequency observations, дубли model_key, несколько lexical heads под одним ключом, повтор независимой модели под разными производными.

Состав top five виден в before/after списках; разность их множеств отделяет новые модели от перестановки. Итог международности сравнивается только при наличии реальных чисел и полных данных. Неизвестные P, значения или частоты не заполняются приоритетом, нулём или выдуманной оценкой. Режим не вычисляет новые формулы и не вызывает платную модель. Реальных before/after расчётов для новых кандидатов пока нет: изменение результата Интераля неизвестно.
