# Сохранение истории — 2026-10-21

PASS. Отказ, исправление, отмена и последующие независимые проверки сохраняются отдельными событиями. Ни одно событие не заменяет предыдущее. Область каждого решения содержит question ID, family ID, язык и конкретный native lexeme ID. Отказ в одной семье не распространяется на остальные.

На реальной очереди выполнены 100 последовательных решений, исправление первого отказа и его отмена, противоречащая слепая проверка и арбитраж `UNCERTAIN`. Для этого вопроса движок сохранил пять событий: `REJECT → DEFER → REJECT`, затем отдельные мнения второго разметчика и арбитра. Цепочка `previous_status` относится к потоку конкретного разметчика, а не смешивает авторов. Повторный импорт той же очереди сохранил отказ.

Регрессионные испытания дополнительно проверяют исчезновение вопроса из обновлённой очереди и его повторное обнаружение, обновление версии источника, сохранение старого снимка, а также устаревание основания арбитража после исправления одной из проверок. Два независимых мнения сравниваются по статусу, конкретной лексеме и типу связи; недостаток оснований не вынуждает положительный или отрицательный ответ.

Отдельный интеграционный тест **дважды действительно строит существующий граф и очередь по официальным закреплённым пробам проекта** для OCUL, PEDE, ALTER, REGUL, CREAT, NAT и INTER. Между сборками сохраняется `ACCEPT_PROPOSED`. Повторная сборка сохраняет исследовательское одобрение, не добавляет графовый verdict и не меняет количество `known`-соответствий. Маркер поколения в тестовом manifest служит только проверке уведомления об обновлении; это не заявленная новая версия внешнего корпуса. Полный многомиллионный граф в этой работе заново не скачивался.

Слепой разметчик получает только собственную историю. После обеих проверок арбитр получает сравнение и пишет отдельное решение с хешем оснований. Пакетная операция сохраняет собственную историю каждого вопроса. Восстановление браузерной копии дало идентичные head и эффективные решения.
