# Очередь ручной проверки — схема 1

`Queue` хранит отдельный SQLite-файл вне репозитория. Никаких таблиц подтверждённого членства или операций записи в v5/v6. Экспорт — детерминированный NDJSON по ID.

| Поле | Значение и ограничение |
|---|---|
| id | `candidate:` + SHA-256 канонического массива [family, language, NFC+casefold(lemma), POS] |
| family, language, lemma, pos | Предложение и оригинальная лемма; POS может быть null |
| lexeme_alternatives | Все source-native Ref, без слияния омонимов и значений |
| proposed_bases | Реальная исходная лексема + конечные проектные соответствия/head ID |
| discovery_paths, evidence_refs | Все узлы, шаги, типы, направления, источники, raw locator, неопределённости |
| sense_description, sense_status | null/unresolved при отсутствии проверяемого значения |
| frequency_observations | Реальные измерения + исходный JSON + hash + commit/file/family/lemma locator; [] = unknown |
| frequency_identity_status | Совпадение языка/написания, не тождество значений |
| match_kind, allomorph_status | Точное начало/путь; новые алломорфы не разрешены |
| uncertainty_reasons, conflicts | Неизвестное значение/POS, другие предлагаемые семьи, ReviewTask графа |
| priority | Отдельный экспериментальный показатель, компоненты и веса |
| group_key | Семья/язык/POS/набор типов операций для пакетной проверки; не лингвистическое объединение |
| review_state | open / rejected / reviewed / split_required / deferred; accepted отсутствует |
| previous_decisions | Упорядоченный append-only журнал: sequence/state/reason/actor/basis fingerprint |
| input_fingerprint | Hash текущего payload; версия источника не входит в идентичность вопроса |
| evidence_changed_since_review | Изменившийся payload сохраняет прежнее решение и требует отдельного внимания |
| active_scopes | Текущие области обнаружения; пустой список не удаляет вопрос/историю |
| establishes_membership | Всегда false |

SQLite: `questions` — текущий материал; `history` — последовательность решений; `scopes` — активные ссылки. Индекс family/language/state ускоряет поиск прежних запретов. Транзакция откатывает неуспешную перестройку scope целиком. История не очищается при деактивации/пересборке графа.

ID обозначает вопрос проверки, а не тождественную лексему. Одинаковые нормализованные строки группируют работу, но все исходные lexical Ref сохраняются. Смена source release не создаёт новый вопрос при неизменных family/language/lemma/POS; меняется payload/fingerprint. Смена POS наследует консервативные отрицательные решения по написанию со ссылкой на исходный вопрос; это запрет автоматического обхода, а не вывод об омонимии. Уже существующий POS-вариант также получает запрет при следующей перестройке.

`Queue.decide(id,state,reason,actor)` требует явного решения, причины и автора. reviewed — завершённая проверка вопроса, не accepted membership. Встроенного принятия членства нет. Передача истории требует сохранять SQLite-файл; NDJSON — читаемый детерминированный backup, автоматический импорт чужого журнала/выдача полномочий не реализованы.

Guard графа применяется к каждому старту и промежуточному узлу; rejected/excluded/split_required/manual_override и текущие ограничения не обходятся через alias/fallback. Известные конечные записи исключаются из новых вопросов. Повторное открытие корпуса не восстанавливает отрицательное членство. Изменения одного источника пересобирают ограниченный scope, но изменяют только затронутые payload; история остальных вопросов остаётся прежней.

Обратный поиск имеет отдельный SQLite `<queue>.reverse` и `reverse-queue.ndjson`. Поле family=unassigned — метка задачи поиска новой основы, не семейство проекта. Несколько исходных отношений группируются в один вопрос язык/лемма/POS, а все реальные основы и отношения сохраняются. Для него действуют те же журнал, fingerprint, наследование запретов и отсутствие accepted.
