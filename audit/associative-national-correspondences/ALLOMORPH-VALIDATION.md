## Разобранные семьи

| Элемент | Документированный контекст | Граница разрешения |
|---|---|---|
| `manu` | FR `manucure`, историческое FR `manicure`, EN `manicure`, DE `Maniküre`, RU «маникюр»: уход за руками/ногтями, Latin `manus` | `mani-` допустимо в этих носителях; нет `man-* → manu`. Французское историческое написание не объявляется современной нормой. Глагольная метафора стрижки изгороди не наследует значение ухода за руками. |
| `regul` | EN `regulate`: `regula → regulare`; FR `réguler`; FR `règlement`: `regula → règle → régler → règlement`; RU «регламент» | `regul-`, `régul-`, `règl-`, `регл-` привязаны к конкретным словам и значениям правил. Для «регламента» сохранены прямой французский маршрут Кузнецова и польское посредничество у Крысина; спор о маршруте не отменяет общего документированного основания. Оплата по `règlement` — другое значение. |
| `creat` | EN `create`, FR `création`, DE `Kreation`, RU «креативный» | Формы `creat-`, `créat-`, `Kreat-`, `креат-` разрешены только для перечисленных контекстов. `креатура` остаётся на проверке: историческое происхождение документировано, современное значение «ставленник» и маршрут требуют отдельного разбора. FR `créatine` восходит к греческому названию плоти; сходство с `création` не подтверждает Latin `creare`. Для RU «креатин» это не автоматический перенос французского решения. |
| `ocul` | EN `ocular`, FR `oculaire`; FR `œil ← oculus`; DE `Monokel ← monocle ← monoculus ← oculus` | У `Monokel` национальная форма в записи — целый исторический носитель компонента, не новая основа корня. Современная морфемная граница не выдумывается. Историческая связь `œil` не доказывает узнаваемость `ocul`. |
| `ped` | FR `pédicure`: `pes/pedis` + `cura`, специалист по уходу за ногами | Нормативный ID v6 `family:ped` и старый v5 `family:pede` сопоставлены явно по закреплённому каталогу. В `pédagogie` документирован греческий компонент «ребёнок»; это опровержение конкретного разбора через Latin «стопа», не готовый отказ corpus membership. |
| `inter` | FR `interposer`, Latin `interponere`, документированный компонент `inter` «между» + `ponere` | Нормативный элемент остаётся предлогом; национальный приставочный компонент не превращает весь глагол в предлог. Наличие продуктивного `inter-` в языке не устанавливает членство произвольного слова. |
| `liber` | FR `libérer`: Latin «свободный»; FR `libraire`: Latin «книга» | В закреплённом нормативном каталоге нет целевого значения/lexical head. Обе условные ветви остаются `UNRESOLVED`; совпадение `liber` не объединяет омонимичные латинские основы. Требуется решение о целевом значении, нормативная форма не меняется. |
| `mut` | FR `mutation` «изменение», DE `Mutation` из Latin `mutatio` | DE `Mut` «смелость» документирован через Germanic `muot`; это другое конкретное основание. Оно не даёт права удалять неизвестные альтернативные связи. |

Полные ссылки и точные source IDs даны в каждой записи; дополнительные пояснения
не являются новыми словарными цитатами. Реестр охватывает конечные контексты
четырёх современных контрольных языков, не заявляет исчерпывающей проверки всех
форм шести языков и не вводит глобальных правил. Других семей в непустых
предложениях очистки нет, поскольку все предложения пока пусты.

## Проверка предложений и исходного корпуса

Прочитаны все шесть NDJSON manifests предложений/исправлений этапов 05–07,
включая историческую v1 и текущую v2 этапа 07, и отдельный JSON data-plan этапа
05. Точные пути, размеры, SHA и число строк — в `EXCLUSION-COVERAGE.json`.
Все шесть файлов пусты; data-plan содержит `NO_DATA_PATCH_NEEDED`. Фактических
предложений удаления, спасённых связей и заблокированных операций — **0**.
Защитные сценарии в regression tests не подсчитываются как реальные спасения.
`BLOCKED-OPERATIONS.ndjson` поэтому пуст; сложные документарные случаи отдельно
сохранены в `UNRESOLVED-CONFLICTS.ndjson` — четыре записи.

Два свежих потоковых обхода прочитали все 256 family buckets и шесть языков:
2 456 543 семьи, 10 078 319 memberships. Все 2 051 production-файл совпали с
сертифицированным baseline по размеру и SHA. Оба `PRODUCTION-INTEGRITY.json`
байтово идентичны; время и RAM вынесены в `RESOURCE-BENCHMARK.json`.
Проверены SHA всех 35 физических файлов UDer/GLeMM/MorphyNet. Совпадение данных
этих источников не превращается в независимые семантические подтверждения.

В точных старых семьях найдены четыре совпадения словарного написания; их
lemma IDs, ordinal, bucket и хеш исходной записи сохранены. Это локализация,
а не подтверждение POS/sense. Отдельно закреплена одна защитная привязка старого
`monokel` к словарному `Monokel`: только конкретный ID и версия, без общего
case folding. Даже она сохраняет lexical identity `UNRESOLVED`.
`family:creat` и `family:mut` из legacy-ID списка v6 отсутствуют как точные
family records текущего v5. Alias-кандидаты (пять для `creat`, шесть для `mut`)
сохранены в `ID-MAPPING-ISSUES.json`; разрешения на них не переносятся.

## Исполнение защиты

`Registry.check` требует точного v5 ID, языка, лексемы и версии источника.
Документированное соответствие или неопределённая применимость блокирует
удаление. Отсутствие записи не доказывает отсутствия связи: для допуска нужны
полная действующая история, разрешённая идентичность/POS/sense и внешний
авторитетный receipt, связанный с хешем всего предложения и реестра. Модельная
уверенность не является receipt. Семейная операция требует полного конечного
scope с числом строк и хешем; проверка использует дисковую дедупликацию.

Обязательный callback подключён к `surface_cleanup.policy.authorize` и
`morphology_review.policy.guard_application`. Без него допуск закрыт. Старые
отрицательные решения не менялись: повторно проверены все семь точных
historical nonmember scopes, соседние области не получили отказов, отсутствие
истории блокирует операцию. Полнота истории по-прежнему `false`.
Структурный shadow-инструмент по-прежнему допускает только доказанные metadata
операции с нулевым смысловым влиянием.

Нормативные определения закреплены commit `ad32277…`; каталог ID — `9fff764…`.
Селектор с SHA и content-addressed snapshots позволяют восстановить реестр
независимо от модели. Проверка JavaScript независимо сверяет документарные
receipts, источники и все proposal manifests. Команды, ограничения и правила
полного повторного прохода — в `associativvordes/national_correspondences/README.md`.
Di, Pr, Sh, SWOW, A, F, P, FAv и FAₐ не изменены и не пересчитаны.
